# 1팀 PRD — 프리런칭

> 모아 둔 것을, 필요할 때 바로 꺼내 쓰게.

| 항목 | 내용 |
|---|---|
| 범위 | 12/12 프리런칭 (MVP) |
| 기준 | 11/18 전체 추가 기획 회의까지의 결정 |
| 바뀔 수 있는 곳 | 링크 수집 범위 (OQ-03, OQ-04), 정보 제공 방식 (OQ-02) — 11/23 전체 회의 |

## 1. 문제

사람들은 이미 매일 저장한다. 문제는 그다음이다. 다시 보지 않고, 다시 보려 해도 못 찾는다.

| 응답 | 비율 |
|---|---|
| 하루 한 번 이상 저장 | 75.0% |
| 구체적 계획 없이 "언젠가 유용할 것 같아서" 저장 | 88.2% |
| 다시 보는 건 월 2~3회 이하이거나 안 봄 | 52.6% |
| 찾는 데 5분 넘게 걸리거나 못 찾음 | 28.9% |

다시 못 쓰는 이유: 저장 위치를 잊음 42.1%, 저장한 사실을 잊음 39.5%, 너무 많음 26.3%, 검색어가 안 떠오름 25.0%, 여러 앱에 흩어짐 19.7%

출처: 디자인팀 1차 유저 리서치 설문 (응답 76명)

## 2. 증명할 것

**저장한 걸 스스로 다시 꺼내 쓰는가.** 수집은 최소로 두고, 다시 쓰게 만드는 데 집중한다.

- 판단: 프리런칭 뒤 2주, 팀원·지인을 빼고 리마인드 클릭이 아닌 스스로 다시 꺼내 본 사용자 수
  - 5명 이상 계속 · 1~4명 2주 더 보고 판단 · 0명 방향 재설정 (11/7)
- 팀 목표: 사용자 10명, 수익 1,000원 (11/16)

## 3. 타깃

이미 저장해 둔 게 많고, 여러 곳에 흩어 저장하고 다시 열지 않는 사람. 첫 사용자는 디프만 동기.

**다른 점:** 내 저장물 안에서만 답한다. 저장한 것에 없으면 없다고 말한다.

## 6. 범위

### 하는 것

- 웹으로 출시 (D-1118-02)
- 링크 붙여넣기 저장 — C-01
- 자동 분류(8개)·요약·키워드·썸네일, 처리 상태 — O-01 ~ O-04
- 원본 사본 서버 저장 — O-05
- 인사이트 홈: 전체 카테고리의 요즘·지난 관심사 — H-01 ~ H-04
- 카테고리 탭 — H-05
- 꺼내 쓰기 챗봇: 저장물 안에서, 좁혀가기까지 — R-01 ~ R-04
- 카카오 로그인, 저장물 삭제(확인 창), 개인정보·외부 LLM 전송 동의 — P-01 ~ P-03

### 하지 않는 것

하지 않는 것은 버린 게 아니라 순서를 뒤로 미룬 것이다.

| 항목 | 이유 | 결정 |
|---|---|---|
| 카톡 내보내기 가져오기 | 아이폰에서 파일을 꺼낼 수 없음 | 보류 D-1118-03 |
| 공유하기로 바로 저장 (PWA) | 웹은 안드로이드 PWA만 가능. 필요하면 앱으로 | D-1118-04 |
| 이미지·동영상·메모 저장 | 개인정보와 처리 비용 | D-1118-06 |
| 갤러리·노션·구글 연동 | 이후 단계 | D-1118-R |
| 챗봇 밖 검색 | 프리런칭 제외 | D-1118-09 |
| 이미지 글자 인식 (웹 OCR) | 웹 품질이 네이티브보다 낮음 | D-1118-07 |
| 인사이트 카테고리 골라 보기 | 이후 추가 | D-1118-08 |
| 푸시·메일 알림 | UT에서 먼저 검증 | D-1118-11 |
| 사용자 카테고리 만들기, 저장하지 않은 정보로 답하기, 휴지통 | 이후 단계 | D-1118-R |

## 7. 정책과 기술 전제

| 항목 | 내용 |
|---|---|
| 플랫폼 | 웹. 공유하기 저장·갤러리·푸시가 필요해지면 앱으로 간다 (설치형 웹앱은 쓰지 않음) |
| 로그인 | 카카오 로그인. 인증은 JWT 방향으로 서버와 맞춘다 |
| 처리 | 저장 요청을 먼저 받고 뒤에서 처리한다. 화면은 실시간 반영이 아님을 전제로 그린다 |
| 배포·문서 | 프론트 Vercel, API 문서는 서버 레포와 Swagger |
| 일하는 방식 | 이 레포의 PRD가 정본, 화면은 피그마, 기능명세서는 기반 문서로 가볍게 |
