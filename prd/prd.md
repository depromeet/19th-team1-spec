## 1. 배경과 문제

사람들은 이미 매일 저장한다. 문제는 그다음이다. 다시 보지 않고, 다시 보려 해도 못 찾는다.

| 응답 | 비율 |
|---|---|
| 하루 한 번 이상 저장 | 75.0% |
| 구체적 계획 없이 "언젠가 유용할 것 같아서" 저장 | 88.2% |
| 다시 보는 건 월 2~3회 이하이거나 안 봄 | 52.6% |
| 찾는 데 5분 넘게 걸리거나 못 찾음 | 28.9% |

다시 못 쓰는 이유: 저장 위치를 잊음 42.1%, 저장한 사실을 잊음 39.5%, 너무 많음 26.3%, 검색어가 안 떠오름 25.0%, 여러 앱에 흩어짐 19.7%

출처: 디자인팀 1차 유저 리서치 설문 (응답 76명)

## 2. 목표와 성공 지표

### 목표

**저장한 걸 스스로 다시 꺼내 쓰는지 증명한다.** 수집은 최소로 두고, 다시 쓰게 만드는 데 집중한다. (11/16 회의)

- 팀 목표: 사용자 10명, 수익 1,000원 (11/16 회의)

### 계속할지 판단하는 기준 (11/7)

프리런칭 뒤 2주 동안, 팀원·지인을 빼고 리마인드 클릭이 아니라 스스로 다시 꺼내 본 사용자 수로 판단한다.

| 사용자 수 | 판단 |
|---|---|
| 5명 이상 | 계속 |
| 1~4명 | 2주 더 보고 판단 |
| 0명 | 방향 재설정 |

### 지표

| 지표 | 언제 |
|---|---|
| 스스로 다시 꺼내 본 사용자 수 | 프리런칭 뒤 2주 |
| 재방문율 | 프리런칭 중 |
| 홈 관심사 클릭률 | 프리런칭 중 |
| 꺼내 쓰기 사용률 | 프리런칭 중 |

측정 방식(이벤트 정의)은 아직 없다 `[확인 필요]`

## 3. 대상 사용자

- 이미 저장해 둔 게 많은 사람
- 여러 곳에 흩어 저장하고 다시 열지 않는 사람
- 첫 사용자는 디프만 동기

**다른 서비스와 다른 점:** 내 저장물 안에서만 답한다. 저장한 것에 없으면 없다고 말한다.

## 4. 사용자 시나리오

한 사람이 링크를 저장하고 다시 꺼내 쓰기까지.

1. **저장** — 어느 화면에서든 + 버튼으로 링크를 붙여 넣는다. 분류나 메모는 하지 않는다.
2. **정리** — 서비스가 알아서 카테고리를 나누고 요약·키워드·썸네일을 만든다. 10초 안팎 처리 중 상태를 보여 준다.
3. **다시 발견** — 앱을 열면 "요즘 이런 데 관심이 많았어요"처럼 관심사로 묶인 첫 화면을 본다. 최근 저장이 적으면 지난 관심사를 보여 준다.
4. **꺼내 쓰기** — "관악구에서 가까운 근교로 쉬러 가고 싶어"라고 말하면 저장물 중 관련된 것을 찾아 준다. "조용한 곳만"처럼 이어서 좁힌다.
