# O · 정리

담당: 서버 · 화면: (피그마 링크)

## 목표

사용자가 직접 분류하지 않아도, 저장하는 순간 다시 찾을 수 있는 형태가 된다.

## 요구사항

### O-01 자동 분류 (카테고리 8개)
상태: 확정 — 8개는 초안, UX 관점에 따라 조정 가능 (D-1118-05)
- 형식(이미지·영상·글)이 아니라 정보의 주제와 쓰임새로 나눈다

| 카테고리 | 더 뽑을 정보 (후보) |
|---|---|
| 맛집·장소 | 장소명, 위치, 장소 유형 |
| 제품·쇼핑 | 제품명, 제품 유형, 브랜드 |
| 레시피·생활 | 요리·청소·수납 등 활용 유형 |
| 업무·학습 | 가이드·템플릿·강의 등 |
| 콘텐츠·아티클 | 기사·영상·블로그 등 |
| 디자인·아이디어 | UI·그래픽·브랜딩 등 |
| 쿠폰·티켓·기프티콘 | 혜택명, 유형, 유효기간 |
| 기타 | 공통 정보만 |

카테고리별 추가 정보는 LLM 테스트 결과로 정한다 (OQ-08)

### O-02 카테고리 바꾸기
상태: 확정 (11/16)
- 사용자는 8개 안에서 바꾸기만 한다

### O-03 공통 정보 생성
상태: 확정 (11/16)
- 모든 저장물에 남는 정보: 원본 링크 · 제목 · 카테고리 · 저장일 · 핵심 요약 · 키워드 · 썸네일
- 이미지는 기본 제외, 서버 공수가 되면 포함. 디자인은 이미지 추가를 염두에 둔다 (D-1118-06)

### O-04 처리 상태 표시
상태: 확정 (11/18, 정책)
- 처리에 10초 안팎. 기본 이미지 → 썸네일 → 완료 순서로 상태를 보여 준다

### O-05 원본 사본 저장
상태: 확정 (11/18)
- 원본 링크가 지워져도 깨지지 않게 서버에 사본을 둔다
- 이미지는 대표 이미지만 압축해서 저장
- 사본 비용과 원본 보기 제공 방식은 미정 `[확인 필요]`

### O-06 중복 제거
상태: 논의 (OQ-07)

## 하지 않는 것

| 항목 | 결정 |
|---|---|
| 사용자 정의 카테고리, 스크린샷 기반 분류, 카테고리 묶음 | 이후 D-1118-R |

## 열린 질문

- OQ-05 "기타"도 검색 대상인지
- OQ-06 여러 카테고리에 걸친 저장물 기준
- OQ-07 중복 제거·유사 링크 범위
- OQ-08 카테고리별 추가 데이터 범위
